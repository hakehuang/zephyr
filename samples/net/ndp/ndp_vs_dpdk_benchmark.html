5. Important Caveats

⚠ “Same condition” is not possible for DPDK in QEMU.
DPDK requires kernel bypass — PCI passthrough (VFIO), huge pages, and poll-mode drivers that directly manipulate NIC hardware registers. QEMU’s emulated NIC (e1000/virtio) strips all of DPDK’s architectural advantages.

This comparison is therefore architectural and clock-normalized. For raw hardware benchmarks, DPDK should be measured on bare-metal with compatible NICs (Intel X710, Mellanox CX-5, etc.), while NDP targets embedded platforms (NXP RT595, Rockchip RK3568, etc.).

6. Key Takeaways

Takeaway 1
Comparable Per-Packet Efficiency
NDP’s 108 cycles/pkt matches DPDK’s 100–200 for similar workloads — achieved without huge pages, SIMD, or hardware offload.
Takeaway 2
Throughput Gap = Architecture
DPDK’s 4–10x throughput lead comes from multi-core RSS, burst processing, and SIMD — server features not applicable to embedded targets.
Takeaway 3
NDP Wins Embedded
87 KB RAM, <1s boot, real-time determinism, and microwatt power: 1000:1 memory advantage over DPDK for the same per-packet work.
